# Core Principles Detailed Execution Rules

> This file details the core principles that must be adhered to in `SKILL.md`.

## 1. Minimal Necessary Changes

- Only insert or append at the user-specified location.
- Do not make broad overwrites to existing files.
- Do not refactor unrelated code without authorization.
- Do not restructure shared logic because of a localized issue.

## 2. UTF-8 and Text Integrity First

- All target files must be read as `utf-8` and written back as `utf-8`.
- Do not rely on terminal display to judge whether file content is intact.
- After writing non-ASCII text, perform at least one real verification:
  - Re-read the file to confirm the added snippet exists.
  - Verify that the snippet does not contain corrupted question mark (`???`) mojibake.
  - Verify that added text remains intact.
- If text anomalies are detected, differentiate between terminal display encoding issues and actual on-disk file corruption.

## 3. Reuse First, Then Create

### Deduplication Process

- Before adding an API method, search by the URL's **pure_path** to check if an implementation already exists in the repository.
- **Prefer using `tools/page_api_index.sqlite3`** (generated by `scan_page_api.py`, version-controlled):
  - A hit on `api_url` + `method` indicates an existing implementation; match paths with variables like `{1}` using rules in `skill_utils/api_path_match.py`.
  - Index entries include `api_name`, `api_desc`, `Author`, `Create Date`, `Update Date`, `method`, `class`, `bases` to determine the origin of the method.
  - Index freshness is automatically maintained by the Preflight 0 hook (7-day threshold, see `doc/preflight_gates_new.md` / `doc/preflight_gates_maintenance.md`). Only when manually adding an API method must you run `scan_page_api.py` to refresh the index immediately.
- If the index is unavailable, fall back to grep searching, covering `.format()`, string concatenation (`+`), and f-strings.
- Search beyond the current file: consider parent classes, sibling API files, and API classes inherited by the active test class instance.

### Branches for Matched vs Unmatched

- If the URL is already implemented:
  - Directly reuse the existing method.
  - Invoke it in the test case according to its established calling style.
- If the URL is not implemented:
  - Add the new method.
  - **After adding the method, you must synchronously run `tools/scan_page_api.py` to refresh `tools/page_api_index.sqlite3`**, keeping the global index up to date.

### How to Update `tools/page_api_index.sqlite3`

1. **Incremental Scan**: Run `tools/scan_page_api.py` — rebuilds fully if the database is empty (id starts from 1); if non-empty, scans all, filters by `Create Date` within 30 days, compares against `(api_url, method)`, and appends new APIs only.
2. **Force Full Rebuild**: `python tools/scan_page_api.py --full` clears and rewrites the entire table, re-indexing ids from 1.
3. **Rule Extension**: URL extraction rules can be appended in `api_extract_rules.json` or `scan_page_api.py`; HTTP method extraction can be added in `REQUEST_METHOD_RULES` (covering `requests.xxx(...)`, `requests.request("METHOD", ...)`, `self.send_msg("get"/"post", ...)`, etc.); URL capture matching rules are added in `skill_utils/api_path_match.py`.

## 4. Ground in Real API Responses

- Assertions must be grounded in **actual API responses** and **actual test execution results**.
- If reference schemas diverge from actual responses, modify assertions rather than forcing assumptions.
- Pay close attention to whether the API method returns the full `response` object or unpacked data like `response.get("data")`.

## 5. Tests Must Form a Closed Loop

- After authoring or modifying code, execute `pytest`. **By default, the task is only complete once the target test cases pass** (unless the user explicitly states in the current session that running pytest is not required).
- Read pytest settings from `config.json` before execution:
  - Working directory: `paths.pytest_workdir`
  - `PYTHONPATH`: `pytest.pythonpath`
  - Command template: `pytest.command_template`
- Record the execution directory, `PYTHONPATH`, exact command, key logs, error details, and final outcome.
- If failures occur, diagnose and repair based on actual errors until tests pass.
- If passing depends on a specific working directory or `PYTHONPATH`, explicitly document it.
- If environment issues prevent passing, clearly distinguish **code issues** vs **environment/network/auth/session issues** and report them to the user.
